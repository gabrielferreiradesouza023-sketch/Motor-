# T-42: Ledger de intenções pendentes e guarda anti-duplicação
Fase: F6-pré  |  Depende de: T-41 (main a913317)
## Objetivo
`_pause_remote` grava `Action(result="intent")` antes do HTTP e um `pause_result` depois. Se o
processo morrer entre os dois (BaseException, OOM, kill), fica uma intenção órfã e nada impede
um novo POST para a mesma entidade no ciclo seguinte. Hoje não há consulta nem guarda para isso.
## Arquivos
src/arb/ledger.py (novo), src/arb/launcher/actions.py, src/arb/doctor.py, src/arb/cli.py
(`arb ops pending [--json]`), tests/test_ledger.py, scripts/check_coverage.py (incluir arb.ledger)
## Escopo
- `pending(connection) -> list[Pending]`: intenções sem `-result`, e resultados `uncertain`,
  com entity_id, meta_id, kind, idade. Leitura pura, ordenação determinística.
- `pause()` remoto recusa nova tentativa para entidade com pendência aberta (erro explícito
  "reconciliar antes"), sem escrever nada.
- `arb doctor`: aviso listando quantidade de pendências; `arb ops pending` humano/JSON.
## Critérios de aceite
Intenção órfã criada por `KeyboardInterrupt`/`SystemExit` injetado no writer aparece no ledger;
segunda pausa da mesma entidade é recusada sem novo POST (contador do MockTransport = 1).
## Testes obrigatórios
Órfã por BaseException; uncertain; pendência resolvida some do ledger; recusa sem POST;
CLI JSON estável; arb.ledger ≥95% no gate de cobertura.
