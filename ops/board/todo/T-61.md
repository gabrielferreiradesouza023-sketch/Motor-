# T-61: Id curto de rastreio (fallback previsto para V-02)
Fase: F4+  |  Depende de: T-41
## Objetivo
A spec (tabela V-02) define: "Se não aceitar o `ad_id` inteiro, usar um id curto mapeado no
banco". Hoje a ponte grava o `ad_id` inteiro no parâmetro de rastreio.
## Arquivos
src/arb/db/migrations/00X_tracking_ids.sql, src/arb/tracker/__init__.py, src/arb/bridge/__init__.py,
src/arb/config.py + config/settings.yaml (`tracking_id_max_length: null` = usar ad_id, comportamento
atual), tests/test_tracking_ids.py, ops/decisions.md (ADR)
## Escopo
- Tabela de mapeamento id curto ↔ entidade, determinístico e sem colisão (detectar e recusar),
  alfabeto e tamanho configuráveis; casamento de vendas aceita os dois formatos.
- Com `null`, comportamento e páginas geradas idênticos aos atuais.
## Critérios de aceite
Venda com id curto casa com a entidade certa; colisão é erro explícito; nenhum valor real de
V-02 é assumido (o humano define o tamanho quando validar).
## Testes obrigatórios
Ida e volta, colisão forçada, ponte com e sem id curto, regressão do casamento atual.
