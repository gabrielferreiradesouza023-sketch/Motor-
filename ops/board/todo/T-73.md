# T-73: Registro assinado das validações humanas (V-01–V-06 e limites)
Fase: F5/F6  |  Depende de: T-72
## Objetivo
`ops/validation-status.json` aceita `"by": "human"` como texto livre. Qualquer agente pode
marcar V-01–V-06, cartão, spend_cap ou host como confirmados.
## Arquivos
src/arb/readiness.py, src/arb/validation.py (novo), src/arb/cli.py
(`arb validate record <item> --evidence "<texto>"`, `arb validate show [--json]`),
tests/test_validation_record.py, ops/decisions.md (ADR)
## Escopo
- Cada item vira registro com `status`, `checked_at`, `evidence` (texto ou referência a
  arquivo) e `signature` Ed25519 do humano; `record` exige tty e chave privada.
- `readiness` ignora registros sem assinatura válida ou vencidos (regra de frescor atual).
- O arquivo versionado atual (tudo `pending`) continua válido e resulta em ✘ para todos.
## Critérios de aceite
Editar o JSON à mão para `confirmed` não muda o readiness; registro assinado muda só o item dele.
## Testes obrigatórios
Registro assinado, edição manual, item desconhecido, sem tty, assinatura de outro item copiada.
