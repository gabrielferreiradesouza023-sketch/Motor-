# T-74: Diagnóstico de host WSL/systemd
Fase: F8+  |  Depende de: T-66
## Objetivo
O humano vai usar Windows + WSL. As unidades geradas são systemd de sistema; no WSL o
systemd precisa estar ligado e a VM pode parar quando não há sessão aberta. Hoje nada avisa.
## Arquivos
src/arb/hostinfo.py (novo), src/arb/doctor.py, src/arb/preflight.py, src/arb/readiness.py,
src/arb/cli.py (`arb service status [--json]`), tests/test_hostinfo.py
## Escopo
- Detectar WSL (`/proc/version`, `WSL_DISTRO_NAME`), systemd como PID 1 (`/proc/1/comm`),
  timezone do host e se as unidades `arb-*` estão instaladas/ativas. Leitura apenas; para o
  estado das unidades, executar `systemctl show <unidade> -p ActiveState,UnitFileState,NextElapseUSecRealtime`
  somente quando o comando existir — nunca start/enable/stop.
- Doctor: aviso "WSL sem systemd" e "WSL pode suspender; não usar para dinheiro real sem
  host sempre ligado". Readiness: `persistent_host` continua exigindo registro humano assinado.
## Critérios de aceite
Saída correta em Linux nativo, WSL com e sem systemd, sem systemctl, unidades ausentes/ativas.
## Testes obrigatórios
Fixtures de `/proc` e saídas de `systemctl show` simuladas por monkeypatch/subprocess falso;
teste estático garante ausência de verbos que alteram estado do systemctl.
